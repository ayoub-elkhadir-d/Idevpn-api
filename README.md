# Ultimate Tunnel Admin

A full-stack foundation for administering Ultimate Tunnel infrastructure. The dashboard, API, and MySQL schema are ready for future Android API integration; VPN connection logic is intentionally out of scope.

## Requirements

- Node.js 20+
- npm 10+
- MySQL 8.0.16+ (InnoDB)

## Local setup

1. Install dependencies from the project root:

   ```sh
   npm install
   ```

2. Create a MySQL database and a dedicated database user:

   ```sql
   CREATE DATABASE ultimate_tunnel_admin
     CHARACTER SET utf8mb4
     COLLATE utf8mb4_unicode_ci;
   CREATE USER 'uta_admin'@'localhost' IDENTIFIED BY 'use-a-unique-password';
   GRANT ALL PRIVILEGES ON ultimate_tunnel_admin.* TO 'uta_admin'@'localhost';
   FLUSH PRIVILEGES;
   ```

   On Namecheap shared hosting, create the database and user in cPanel and use the exact host, database name, and username shown there.

3. Copy `.env.example` to `.env`, set `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME` for your MySQL instance, and generate a dedicated encryption key:

   ```sh
   node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
   ```

   Put the generated value in `CONFIG_ENCRYPTION_KEY`. Back it up securely; encrypted protocol credentials cannot be recovered without this key. Keep `.env` private; it is ignored by git.

4. Apply the database migrations:

   ```sh
   npm run db:migrate
   ```

5. Create the first admin interactively. The password is entered without being echoed and must be at least 12 characters (and no more than 72 UTF-8 bytes, the bcrypt limit):

   ```sh
   npm run admin:create
   ```

6. Start the API and frontend:

   ```sh
   npm run dev
   ```

   Open [http://localhost:5173](http://localhost:5173). The Vite development server proxies `/api` requests to the Express API on port `4000`.

The migration command creates the tables in order on the selected MySQL database. The project does not include seed scripts; create the initial admin using the command above.

## Production

Build both workspaces with `npm run build`, then run `npm start` to start the API. Set `NODE_ENV=production` and `SESSION_COOKIE_SECURE=true` when serving behind HTTPS. Configure your reverse proxy to route `/api` to the API and serve the built frontend from `packages/web/dist`. Set `TRUST_PROXY=true` only when the API is behind a trusted reverse proxy.

For cPanel deployment, set `VITE_API_BASE_URL` to the HTTPS API origin before building and configure `FRONTEND_ORIGIN` to the exact HTTPS frontend origin in the API environment. See [DEPLOYMENT.md](./DEPLOYMENT.md) for Namecheap cPanel startup, CORS, cookie, database, and environment settings.

```text
    src/
      auth/              Session creation and protected-route middleware

      routes/             Authentication and protected admin API
  web/
    src/
      api/               Credentialed API client
      auth/              Admin session state
      components/        Responsive dashboard shell and navigation
      pages/              Login, dashboard, and future-feature placeholders
```

## Authentication and security

- Admin passwords are hashed with bcrypt (12 rounds); there is no default admin or public registration route.
- Sign-in creates a cryptographically random, 12-hour server-side session. Only its SHA-256 digest is stored in MySQL.
- The session token is sent in an `HttpOnly`, `SameSite=Strict` cookie; enable the `Secure` flag in HTTPS deployments.
- Login attempts are rate limited. API responses use Helmet security headers, JSON request bodies are size limited, and SQL uses parameterized queries.
- Apply new SQL files in `packages/server/migrations/` using `npm run db:migrate`. Applied migration names are recorded in `schema_migrations`.
- Configuration protocol payloads (including passwords, UUIDs, and WireGuard keys) are encrypted with AES-256-GCM before being written to MySQL. The encryption key is separate from the database and session secrets.

Database IDs are UUID strings generated by the application. Migrations use InnoDB, MySQL `JSON`, foreign keys, and MySQL-compatible check constraints. Rewritten migrations initialize a fresh MySQL database; they do not transfer existing PostgreSQL data. Back up the PostgreSQL database and plan a separate, verified data export/import before switching a live installation.

## API foundation

- `GET /api/health` — API and database health check
- `POST /api/auth/login` — authenticate an admin
- `GET /api/auth/me` — current admin (protected)
- `POST /api/auth/logout` — revoke current session
- `GET /api/admin/dashboard` — protected overview data
- `/api/admin/configurations` — protected configuration CRUD, filtering, pagination, duplication, lifecycle, and protocol capability endpoints

The admin sidebar is intentionally limited to Dashboard, Configurations, and Users. Configuration names may identify a carrier or network; logo URLs and protocol-specific settings are managed directly on each configuration. Migration `003_simplified_configurations.sql` adds the logo URL and allows new configurations to omit legacy carrier/server associations. Existing carrier/server records, foreign keys, and configuration references are preserved.

The configuration manager supports distinct VLESS, VMess, Trojan, Shadowsocks, WireGuard, and Hysteria 2 schemas with server-side validation. Protocol payloads remain encrypted at rest and visible only through the authenticated admin API. No public configuration endpoint is exposed. The Android VPN engine is not in this repository, so none of these protocols are marked compatible and publishing is blocked; administrators can save drafts and prepare metadata until engine support is verified. Dashboard statistics remain placeholders until infrastructure and Android-facing APIs are integrated.

Run backend schema, encryption, and auth tests with `npm run test --workspace @uta/server`; run the complete type-check and production bundles with `npm run build`.
